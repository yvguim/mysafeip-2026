# Using MySafeIP

[Index](../../README.md) · [Overview](overview.md) · [Installation](installation.md) · [Français](../utilisateurs/utilisation.md)

## Register or remove an IP address

1. Sign in and open the IP address page (`/ips/config/`).
2. Check the detected address before saving it, especially behind a proxy or VPN. You can enter a single IPv4 or IPv6 address instead and add a description.
3. Choose a lifetime from 1 to 720 hours or mark the entry permanent if it should not expire. Your profile lets you change the suggested default. Save and check that the address appears in the list.
4. Remove the entry when it is no longer needed. MySafeIP removes it from the list; the external system must then remove the matching rule. The same IP may still be present in another entry.

## Share an instant-access link

1. Open the instant-access page (`/instant-access/config/`).
2. Enter the destination URL (`http://` or `https://`), a description, and a lifetime from 1 to 720 hours. Prefer a short lifetime to a permanent link.
3. Copy the link generated by MySafeIP and share it only with the intended recipient. A link starting with `127.0.0.1` won't work from another machine; see [Installation](installation.md).

```text
Link owner ── shares the link ──> Visitor
                                    │ opens the link without an account
                                    ▼
                                 MySafeIP ── registers the IP under the link owner's account
                                    │ displays a page before redirecting
                                    ▼
                                 Destination
```

The **link lifetime** and the **IP lifetime** are separate: a new IP entry created by opening a link lasts 24 hours. Expiring the link does not immediately remove IPs already created. **Manually deleting a link from its list**, however, also removes its remaining associated IP entries. If the link is no longer listed, check the IP list and remove entries that should no longer be there. This does not directly revoke a rule cached by an external system.

Anyone who has the link can use it while it is valid. Don't post it publicly, and don't treat it as a one-time link or a replacement for authentication at the destination.

## Protect your account

- In your profile, you can change your password and set the default lifetimes for IPs and links.
- To enable TOTP, select the two-factor authentication option and save. Scan the QR code in your authenticator or enter the key manually. Protect that key like a password. Verify that you can sign in with a code before closing your current session, for example in a private window.
- An administrator can open the account list (`/users/read`) and access the interactive documentation at `/docs` after signing in. Don't assume an administrator can see every IP: that setting is disabled in the supplied Compose configuration.

## Read IPs from an integration

In the profile of the account that should read the list, create an API token and store its key and secret in your integration's secret store. The script exchanges them via `POST /token-signin` (form fields `key` and `secret`) for an `access_token`. It then calls `GET /ips/config/` with `Authorization: Bearer …` and `Cli: 1` to get JSON instead of HTML. The response contains `owner`, `value`, and `description` for each visible entry.

API key authentication does not use a TOTP code: don't share the key or secret. Delete a compromised key in your profile and never log tokens. Validate the response before changing rules; distinguish a valid empty list from an error or HTML response. Account for IPs that are no longer listed each time your integration syncs.
